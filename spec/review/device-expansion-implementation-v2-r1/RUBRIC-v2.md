Read-only reviews of identical frozen artifacts, identified by commit and/or SHA256 manifest including research/spec sources and evidence. Full three rubric ballots before grading; majority approval of same rubric version required. Full three valid grading ballots required. Membership changes only for recorded actual execution/availability failure; never replace dissent. Reviewers receive no peer scores before submission. Fresh independent grading contexts where possible.

All categories below apply to each item at both stages:

- EVIDENCE: authoritative own-model/revision/page traceability for interfaces, commands, parser grammar, unit/range/option and module limits; real supported subset distinguished from passive hints, proposed behavior, simulator evidence and physical validation. Manufacturer rename aliases need exact model matching. No cross-model guesswork or unsupported interface substituted.
- API: coherent useful typed capability subset; channel/slot/port/unit semantics, immutable exact-endpoint inventory, capability gating and error behavior; vendor-neutral core contracts only, proprietary rules outside core; passive static registration, no hidden probe or unsupported advertised operations. Module identity, parent ownership and topology explicit; no fictitious independence from mainframe session.
- PROTOCOL: exact command/reply/framing/parsing/status/overload/error rules, bounded allocation and finite deadlines, no silent recovery/retry; mode/options preconditions validated; whole-operation serialization and fail-fast quarantine; owned/borrowed close and cancellation defined. Output/relay/digital mutations explicit; configure or close must not silently activate hardware. Instrument inability to disable an output must be represented honestly.
- PARITY: Rust/C# equivalent supported operations and errors; sync, workers and true native paths honestly gated; static AOT-compatible registration without reflection/runtime discovery. Concrete executable Linux/Windows x64 strategy at spec stage and actual source/packed native proof at implementation stage; .NET8/10. Driver/SDK AOT evidence must not imply unrelated host compatibility.
- VALIDATION: independent exact traffic/value/units/status/error acceptance cases for every exposed operation plus parser negatives/bounds/model/module distinctions; meaningful ownership/quarantine/serialization/cancellation/pending-IO deadlines; rejected config before acquisition, immutable caller data and correct selected-route gating. Existing corpus/generation/regression checks retained. Implementation requires actual execution and artifact/input identity, not planned tests. Unavailable physical evidence clearly excluded from software conformance claims.
- DELIVERY: independently distributed external Keysight/Tektronix packages, core artifacts free of external implementations; deterministic static registration and frozen capabilities, examples/prerequisites and supported/deferred behavior documented. Reproducible external generator/TestKit/CI/package validation and exact SDK pins. Public old versions never represented as containing additions; coordinated future release clearly distinguished. No unauthorized hardware, publication or merge.

Scoring anchors for each category:0–4 absent/incorrect;5–7 partial with substantial gaps;8.0–9.1 useful with material evidence/design/validation gaps;9.2–9.5 complete and independently inspectable for declared scope with minor documented limits;9.6–10 unusually comprehensive. At spec stage score concrete specified design, manual-backed examples and executable acceptance plan, without demanding nonexistent implementation. At implementation stage require actual code, tests and source/packed consumers/platform evidence. Scope cannot be narrowed merely to improve grades.

Rubric ballot must be explicit APPROVE or REQUEST_CHANGES with reasons and concrete amendments. Grading response must identify member, actual model/effort, rubric, frozen revision/manifest; numeric score and threshold-derived vote for every category/item, evidence and confidence/limitations; mandatory defects, prioritized actionable changes and requested amendments. Required uninspectable evidence is UNVERIFIED. Final report records every score, range/median, votes, minority findings and disposition, all ballots and actual artifact revisions.
