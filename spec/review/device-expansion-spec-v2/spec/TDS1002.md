# Tektronix TDS1002 — scalar scope contract v1

The user confirmed **TDS1002**, without A or B. This is a proposed manual-derived software subset, not hardware validation. Primary sources are `research/TDS1002-programmer-071107504.pdf` (071-1075-04) and `research/TDS1002-user-071106400.pdf` (071-1064-00). Their source URLs, byte hashes and model/interface applicability are retained in `research/TDS1002-SOURCES.json`. The later 077-0444-01 programmer manual is corroboration, not a reason to use B-only commands.

Relevant programmer printed pages: 1-1–1-2 (module interfaces),2-49–51 (acquisition),2-68–70 (probe/scale),2-94–95 (DESE),2-133 (HEADER),2-138–141 (main timebase/view),2-157–163 (immediate measurements),2-169–170 (OPC),2-241 (VERBOSE),3-4–8 (status/event masks and consumption),3-23–24 (measurement warnings). The own-model user manual printed147/PDF165 demonstrates source CH1, peak-to-peak measurement and result 5.16E0 with a 10X probe; printed153–156/PDF171–174 gives vertical/timebase limits.

## Explicit factory, identity and interface

Use external Rust module `tds1002` with:

- `Factory::new(Vec<Binding>, Arc<dyn Connector>) -> Result<Factory>` and optional `with_native_connector(Arc<dyn AsyncConnector>)` under the async feature.
- `Binding { endpoint: Endpoint, configuration: Configuration }`.
- `Configuration { communication_module: CommunicationModule, channel_1_probe: Probe, channel_2_probe: Probe, commissioning: Commissioning }`.
- `CommunicationModule::{Unknown,Tds2Cm,Tds2Cma,Tds2Cmax,Tds2Mem}`. Only CM/CMA/CMAX are admitted in this GPIB subset; MEM has RS232 but no GPIB and is rejected before acquisition.
- `Probe::{Unknown,X1,X10,X100,X1000}`. These are the supported non-B voltage-probe factors; do not inherit 20/50/500 or a current-probe YUNIT command from B/TPS models.
- `Commissioning::{Unknown,QualifiedGpibNormalModeConfirmed}`.

C# exposes corresponding `Tds1002Factory`, `Tds1002Binding`, `Tds1002Configuration`, `Tds1002CommunicationModule`, `Tds1002Probe` and `Tds1002Commissioning` types. It accepts the bindings, `IScpiConnector` and optional genuine `IAsyncScpiConnector`. Freeze/copy all endpoint configurations. Require 1–4096 bindings. Reject empty/oversized lists, unknown/undefined enums, normalized duplicate endpoints, wrong scheme, blank addresses and unbound endpoints before acquisition.

Canonical factory ID is `tektronix.tds1002`. Manufacturer is case-insensitive `TEKTRONIX`. Exact model aliases are `TDS1002` and the documented IEEE identity spelling `TDS 1002`; A/B identities never match. Endpoint scheme is `scpi`, with externally commissioned addressed GPIB through an installed CM/CMA/CMAX module. Do not infer direct USB or a B-model TEK-USB-488 path. RS232, printer, CompactFlash and USB transports are deferred. Metadata, matching and opening perform no commands, identity probes, reset or interface discovery.

071-1075-04 supports non-B TDS1000 instruments and their applicable communication modules without borrowing the TDS210/220-specific FV/CMV restrictions. The own-model user manual applies to FV1.00 and later; commissioning affirms actual source applicability. The unsuffixed immediate source setter is demonstrated by that user manual. Later own-applicable077-0444-01 explicitly clarifies `MEASUrement:IMMed:SOUrce[1]?`; omitting the optional1 is the old-model query used here, while MATH/SOURCE2 capabilities remain excluded. No invented firmware-query command or B-only capability is introduced.

Required operations and execution modes are checked on the selected exact binding before acquisition. Genuine native async is advertised only when supplied; blocking connectors use the SDK worker paths. Register this factory explicitly. Do not mutate the existing unqualified MDO3024 profile to impersonate TDS1002.

## Commissioning and complete-message host

Qualified commissioning affirms exclusive stable control; correct connected voltage probes and matching channel attenuation settings; main horizontal view; YT display; normal (not AUTO) triggering; Trigger View inactive; suitable signal/trigger source, slope, level and coupling; a clean message boundary and clean status/event state; DESE 255; and no other controller/front-panel changes during the handle lifetime. Trigger source/level/slope are configured externally and preserved. Normal triggering avoids AUTO Scan mode at 100 ms/div or slower; a missing trigger may legitimately time out.

The host enforces finite deadlines and a 256-byte scalar allocation/body bound, removes only GPIB LF/EOI framing and preserves body whitespace. Binary blocks must be rejected before any header is removed. Choose a deadline long enough for the configured timebase and trigger wait;50s/div can require hundreds of seconds. A shorter deadline may fail normally. No USB/serial-specific framing is assumed.

## Shared communication/status prefix and completion

Every supported operation begins with these separate messages:

1. Write `:HEAD OFF`.
2. Write `:VERB ON`.
3. Query `:DESE?`, require integer 255.
4. Query `*ESR?`, require integer 0.

HEADER OFF suppresses response headers. VERBOSE ON is also required because it controls discrete **argument** keywords, not only header spelling. These are explicit global communication-format changes, left in effect after completion/close. DESE is verified, never changed silently. A different valid mask is Device; malformed/out-of-register-range data is Parse. A nonzero valid ESR is Device. Stop immediately on failure before later operation traffic.

After an operation's final action/value check, query `*ESR?` and require0. A write-only setter succeeds when its write and this status check complete; no calibrated physical readback is promised. Immediate measurement warnings 541–549 can accompany a finite value and set the execution-error status bit, so the post-status query is required before returning a Valid quantity.

`*ESR?` is read-clear and affects the association of summarized unread events with the event queue, as described in the manual. Status consumption is part of this explicit API behavior. No `*CLS`, DESE setter, error-queue drain, retry or suppression is emitted. Initial event/status state is commissioned externally; a nonzero preflight quarantines rather than being quietly cleared and ignored. *OPC? does not itself set the OPC ESR bit.

## Ten supported neutral operations

The following actions occur between prefix and final ESR check. Numbers use the already qualified invariant E11 formatter: 12 significant digits, uppercase E, signed exponent with at least two digits; normalize .NET exponent padding to Rust. Structural arguments are checked before even the two format writes.

### Main timebase

SetTimebaseScale accepts only exact binary64 values from the non-B TDS1002 nominal 1–2.5–5 sequence from 5 ns/div through 50 s/div. The set is `{5e-9}` plus `{1,2.5,5} *10^e` for integer e=-8 through1. Match the binary64 values parsed from their canonical decimal scientific literals; do not accept arbitrary values and rely on instrument rounding.

- Before SetTimebaseScale and ReadTimebaseScale, query `:HOR:VIEW?` and require `MAIN`. Known `WINDOW` or `ZONE` is Device; other tokens Parse.
- Setter writes `:HOR:MAIN:SCA <seconds_per_div>`.
- Reader queries `:HOR:MAIN:SCA?` and returns Second. A finite value outside the admitted nominal set is Device, except malformed/nonfinite/giant numeric data is Parse as below.

The driver does not silently switch a window display to main view or return a main-scale number while implying it is the window scale.

### Channels1 and2

SetChannelScale accepts nominal scales computed from integer millivolts `m` in `[2,5,10,20,50,100,200,500,1000,2000,5000]`: first multiply integer `m` by the frozen integer probe factor, then divide once by 1000.0 as binary64. Match that canonical binary64 value; do not multiply a rounded BNC floating value by the factor. this deliberately narrower software subset avoids any fine/coarse rounding ambiguity. Query `:CH<n>:PRO?` and require the configured integer factor before writing `:CH<n>:SCA <volts_per_div>`. A different documented factor 1/10/100/1000 is Device; undocumented values are Parse. The display scale includes attenuation; it is not the BNC-only scale. Physical probe connection/truth is external and software bounds do not provide input protection.

SetChannelDisplay writes `:SEL:CH<n> ON` or `OFF` for the Boolean argument. SetChannelCoupling accepts only the exact neutral symbols `AC`, `DC`, `GND` and writes `:CH<n>:COUP <symbol>`. Channel 0/3/etc, unknown symbols and invalid nominal scales fail before all IO. No implicit probe attenuation or unit setter is emitted. CH:YUNIT is not supported on this non-B model.

### Acquisition control

- Run writes `:ACQ:STOPA RUNSTOP`, then `:ACQ:STATE RUN`. It resumes the existing acquisition mode and trigger settings; completion means started, not a complete new record.
- Stop writes `:ACQ:STATE STOP`. It stops acquisition, not electrical inputs or every possible instrument output. It is not an emergency-stop/safe-shutdown API.
- Single writes `:ACQ:STOPA SEQ`, then `:ACQ:STATE RUN`. It starts a new single sequence with the current acquisition mode; it returns after the status check, not after a trigger or all averaging acquisitions. The fresh scalar methods below provide an explicit completion wait.

### Fresh Vpp and frequency

MeasureVpp(channel) and MeasureFrequency(channel) perform this exact additional sequence after the prefix:

1. Query `:HOR:VIEW?` => `MAIN`.
2. Query `:DISP:FORM?` => `YT` (`XY` is Device; other tokens Parse).
3. Query `:TRIG:MAIN:MODE?` => `NORMAL` (`AUTO` is Device; other tokens Parse).
4. Query `:SEL:CH<n>?` => `1` (`0` is Device; other bodies Parse).
5. Query `:CH<n>:PRO?` => frozen probe factor.
6. Write `:ACQ:STATE STOP`.
7. Write `:ACQ:MODE SAMPLE`.
8. Query `:ACQ:MODE?` => `SAMPLE`. Known `PEAKDETECT` or `AVERAGE` is Device; other tokens Parse.
9. Write `:ACQ:STOPA SEQ`.
10. Query `:ACQ:STOPA?` => `SEQUENCE` (`RUNSTOP` is Device; other tokens Parse).
11. Write `:ACQ:STATE RUN`.
12. Query `*OPC?` => exact `1`; anything else is Parse.
13. Query `:ACQ:STATE?` => `0` (`1` is Device; other bodies Parse).
14. Query `:ACQ:NUMACQ?` => integer 1. Other valid counts 0..2147483647 are Device; malformed/out-of-range are Parse.
15. Write `:MEASU:IMM:SOU CH<n>` — **without SOURCE1**.
16. Write `:MEASU:IMM:TYP PK2PK` for Vpp, or `FREQ` for frequency.
17. Query `:MEASU:IMM:SOU?` => `CH<n>` (the other valid channel is Device; other tokens Parse).
18. Query `:MEASU:IMM:TYP?` => `PK2PK` or `FREQUENCY`, respectively. Other documented non-B measurement types are Device; unknown tokens Parse.
19. Query `:MEASU:IMM:UNI?` => exact quoted`"V"` or`"Hz"`. Other documented non-B units`"V"`,`"s"`,`"Hz"` are Device; unknown or unquoted units Parse.
20. Query `:MEASU:IMM:VAL?` => scalar.
21. Query final `*ESR?` => integer 0, before returning the quantity.

This intentionally stops any prior acquisition, selects SAMPLE mode, starts and waits for a new one-record single sequence and leaves acquisition stopped in SAMPLE/SEQUENCE. It replaces a prior average/peak-detect acquisition mode; no mode restoration or implicit restart occurs. It preserves trigger source/level/slope and does not enable a hidden channel. Immediate VALUE calculates on the completed record; **VALUE alone is not proof of a new acquisition**.

OPC 1 alone is insufficient because it returns immediately if no busy sequence exists. Mode/stop-after/count checks plus status under verified DESE catch ignored SET commands (for example Trigger View), stale/Scan records and ordinary setting errors. No guard proves external hardware truth or calibrated signal quality beyond the documented event/value contract.

## Exact scalar and token policy

NR3 bodies require optional leading sign, one or more integer digits, optional point followed by one or more fraction digits, mandatory E/e, optional exponent sign and 1–3 exponent digits. No spaces, units, headers, lists, blocks or non-ASCII characters are accepted. A nonzero mantissa that underflows to binary64 zero is Parse; an actual zero mantissa is handled by the measurement domain below. Nonfinite values or absolute magnitude at least 1e30 are Parse, with this measurement-specific exception: exact parsed positive 9.9e37 is the documented invalid measurement sentinel and is **Device**, never Overload/Valid. The sentinel can mean hidden source, Trigger View, Scan/XY or no waveform; do not fabricate a single physical cause.

Vpp may be zero but cannot be negative; frequency must be strictly positive. A negative Vpp, zero/negative frequency or numeric setting outside its admitted domain is Device. Return quantity unit Volt or Hertz and Valid only after successful post-status. No nominal 60 MHz bandwidth cutoff is invented as a parser bound.

Integer register/count/probe bodies use optional leading`+` followed by ASCII digits, no minus/decimal/exponent/space. Require their stated numeric domain; allow leading zeros. The Boolean SELECT/ACQSTATE and OPC bodies remain exact 0/1 forms as listed. VERBOSE ON yields full discrete tokens. Documented non-B measurement types are `FREQUENCY`, `MEAN`, `PERIOD`, `PK2PK`, `CRMS`, `MINIMUM`, `MAXIMUM`, `RISE`, `FALL`, `PWIDTH`, `NWIDTH`. These are the full keyword spellings under VERBOSE ON; B/TPS-only math/power types are not added.

## Lifetime, unsupported operations and delivery

Serialize the entire transaction under one SDK lease. Structural invalid arguments perform no IO and preserve health. Once IO begins, timeout/transport/parse/Device or active cancellation failure quarantines the session. An acquisition may still be waiting/running after timeout; no automatic STOP, clear, reset, drain or cleanup is emitted. External resynchronization/recommissioning and reopening are required. Owned host resources close once; borrowed resources remain open; close sends no device commands and leaves communication format/device state changed as documented.

Do not advertise waveform capture, trigger source/level/slope setters, identity, reset, shutdown, USB, file system, math/current channels or generic MDO commands. These are deferred, not claimed impossible on every model. Future waveform transfer requires a separate 2500-point preamble/scaling/framing contract and bounded-body API; it cannot use this 256-byte scalar backend.

All implementation and exact Tek grammar stay in `instrument-components-tektronix`. Core already has these ten neutral operations; no new core contract is needed. Use the current compatible immutable SDK producer/tool pins and checksum-joined development feed for source and packed proof. Public alpha.1 does not include the new factory. Execute Rust/C# sync/native/worker consumers, .NET Native AOT 8/10 on Linux/Windows x64, actual native binary checks and intentional warning-probe failure. Physical bench evidence, publication and merge remain subsequent work.
