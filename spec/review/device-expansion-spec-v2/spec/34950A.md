# Agilent / Keysight 34950A — static byte IO contract v1

This module uses the single 34980A parent handle and lease defined in `34980A.md`. Primary evidence: `research/34950A-user.pdf`, printed/PDF 19–23 for channel widths and static IO, 31–34 for buffered operations; `research/34980A-programming.pdf`, printed/PDF 160–161 (direction), 175–176 (handshake state), 181–184 (polarity/width), 568–570 (input data), 596–597 (input memory), 756–757 (output data), 759 (drive), 769–770 (level), 773–774 (output memory).

## Frozen byte-only inventory

Each port binds positive logical port ID, slot1–8 and local channel 101–104 or 201–204. Bank1 is 101–104; bank2 is 201–204. Derive the bank's first channel as 101 or 201, then add `1000*slot` for bank-scoped query addresses. Do not send bank queries to a non-first channel.

Freeze direction Input or Output. ReadByte is admitted only on Input; WriteByte only on Output. Enforce selected port/direction before any IO. There are eight separate byte ports per module; do not infer word/lword anchor numbering or allow a zero logical port. Byte writes are inclusive 0–255, with zero valid and no truncation. A `u32` API value 256 or more is InvalidArgument before all guard queries.

The initial electrical policy is normal polarity, unbuffered, handshake lines high impedance; input threshold 2.5 V; output drive ACTive and logic-high level 3.3 V. The application configures and commissions these settings before opening and accepts that output ports may already be driving. It also disables input/output memory starts, INTR-triggered/pattern actions, digital counters and other autonomous actions that can change the admitted bank, keeping them disabled throughout the handle lifetime. Current memory-off and HIMP readbacks do not prove that an already-armed external trigger cannot start memory later. The driver verifies them; it never silently configures direction/width/polarity/threshold/level or enables an output as a setup step. A future configurable electrical policy can extend the immutable binding, but is outside this initial subset.

## Exact transaction and guards

For selected native address `a` and derived bank-first address `b`, every read or write performs this prefix in order:

| Query | Expected body | Valid but wrong => Device | Other => Parse |
|---|---|---|---|
| `:CONF:DIG:WIDT? (@p)` for all four addresses p of the selected bank, ascending | `1` each | `2`, `4` | Other |
| `:CONF:DIG:DIR? (@a)` | `INP` for read, `OUTP` for write | The other documented token | Other |
| `:CONF:DIG:POL? (@a)` | `NORM` | `INV` | Other |
| `:CONF:DIG:HAND:STAT? (@b)` | `HIMP` | `OFF`, `ON` | Other |
| `:SENS:DIG:MEM:ENAB? (@b)` | `0` | `1` | Other |
| `:SOUR:DIG:MEM:ENAB? (@b)` | `0` | `1` | Other |

Read-only width guards cover all four ports of the selected bank, even unbound ports. This proves an adjacent WORD/LWOR anchor is not consuming the selected non-anchor byte; checking only channel 102/104/202/204 would not establish that. The queries do not change those other ports.

The width query returns **numeric byte counts** `1`, `2`, `4`, not `BYTE`, `WORD`, `LWOR`. HIMP is distinct from OFF: OFF still drives handshake pins. Memory enable queries apply to the first port of the bank, even when the selected port is 102/103/104 or 202/203/204.

A read then queries `:SENS:DIG:THR? (@a)` and requires numeric 2.5, followed by `:SENS:DIG:DATA:BYTE? DEC,(@a)`. SENS preserves direction and returns the output latch on an output port, which is why the prior input direction guard is mandatory. Do not replace it with MEAS:DIG?: that would reconfigure input and reset polarity/threshold defaults. The explicit DEC format avoids inherited output-format assumptions; this response is unaffected by FORMat:READing metadata fields.

A write instead queries `:SOUR:DIG:DRIV? (@a)` requiring `ACT` (`OCOL` is Device; other tokens Parse), then `:SOUR:DIG:LEV? (@a)` requiring numeric 3.3. It then writes `:SOUR:DIG:DATA:BYTE <value>,(@a)` using the ordinary unpadded decimal integer 0–255. SOUR data writes automatically select output and width: the prior guards ensure that those are already the admitted states, rather than concealing a direction/group transition that could clear memory or scan configuration.

Every guard stops at its first failure before any later query/write. Wrong numeric threshold or level is Device; malformed/nonfinite numeric bodies are Parse. Accept strict ASCII decimal/scientific grammar: optional leading sign, digits, optional point with digits on both sides, optional E/e exponent with optional sign/digits. Require absolute value below 1e30. Numeric equality is exact parsed binary64 equality to 2.5 or 3.3; no readback tolerance is needed for these exact requested settings/response precision. No setting write is emitted by a read or a failed guard.

## Result and failure contract

A sampled byte response is one or more ASCII decimal digits representing 0–255. Leading zeros are permitted; signs, decimals, exponent notation, CSV, whitespace, radix prefixes and values over255 are Parse. Return a neutral Count/u32, including zero. A write returns Unit when its write completes, without claiming physical pin observation or a calibrated level.

No buffered acquisition/output, word/lword, direction setters, handshake, interrupt control, arbitrary trace or checked shutdown is supported. Close leaves digital states unchanged. IO/parse/Device/cancellation failure quarantines the **parent**; no other module view may continue. Native/worker/ownership contracts follow the mainframe. Hardware and physical electrical compatibility remain unvalidated.
