# Agilent / HP 33120A — extracted contract v2

This is a proposed manual-derived software subset, not hardware validation. Primary source: `research/33120A-user.pdf`, 33120-90006, Edition 6, March 2002. Relevant printed pages: 56–67 (PDF 58–69), command quick reference 128–132, and configuration commands 145 onward. The actual printed-57/PDF-59 frequency-table image was inspected: its minimum is **100 microhertz = 0.0001 Hz**, not 100 millihertz. A rendered copy is `spec/33120A-frequency-table.png`.

## Admission and physical behavior

Canonical ID `keysight.33120a`; exact `33120A`; case-insensitive manufacturer aliases `HP`, `HEWLETT-PACKARD`, `Agilent Technologies`. The initial factory accepts commissioned GPIB SCPI through endpoint scheme `scpi`. RS232 exists but serial host configuration is deferred. Metadata/open send no IO. Require exclusive access, a clean response boundary, finite deadlines, 256-byte complete ASCII replies and LF framing stripped without altering the body.

**The main output is always on.** Any configuration write can immediately alter the signal. Close releases resources and cannot disable output. Do not advertise OutputEnable, output-state query, shutdown or reset as a substitute for output isolation. The connector's physical source impedance is fixed 50 Ohm; `OUTP:LOAD` is load accounting, not an impedance switch.

## Useful initial subset

Support existing FunctionGenerator.SetFrequency, SetAmplitude (Vpp), SetOffset and ReadFrequency for a frozen, explicitly commissioned **continuous sine / 50 Ohm load accounting / VPP** setup. Other waveforms, adjustable load, burst/modulation/sweep and arbitrary data are deferred. There is no Pulse waveform, and Triangle must not be mapped to Ramp.

The user commissions a suitable physical load and confirms the output may be changed. No front-panel/second-controller changes may occur during exclusive use. Readbacks verify settings, not physical termination or calibrated output.

Each operation first queries and checks this exact guard prefix; stop at the first failure:

| Query | Expected body | Known wrong body => Device | Malformed/unknown => Parse |
|---|---|---|---|
| `:FUNC:SHAP?` | `SIN` | `SQU`, `TRI`, `RAMP`, `NOIS`, `DC`, `USER` | Other |
| `:OUTP:LOAD?` | numeric 50 | Other positive finite number, including documented high-Z sentinel 9.9e37 | Nonpositive/non-numeric |
| `:VOLT:UNIT?` | `VPP` | `VRMS`, `DBM` | Other |
| `:AM:STAT?` | `0` | `1` | Other |
| `:FM:STAT?` | `0` | `1` | Other |
| `:BM:STAT?` | `0` | `1` | Other |
| `:FSK:STAT?` | `0` | `1` | Other |
| `:SWE:STAT?` | `0` | `1` | Other |

No guard changes modes or disables modulation implicitly. All queries are documented own-model commands, without the newer generic `SOUR` prefix.

After the prefix:

- SetFrequency writes `:FREQ <hz>`, finite 0.0001 through 15000000 Hz inclusive.
- SetAmplitude queries `:VOLT:OFFS?`, validates the requested Vpp against that offset, then writes `:VOLT <vpp>`. Requested Vpp is finite 0.05 through 10 inclusive.
- SetOffset queries `:VOLT?`, validates the requested offset against that Vpp, then writes `:VOLT:OFFS <volts>`. The initial structural offset bound is finite absolute value at most 4 V. The two coupled inequalities intersect at Vpp = 2 V and offset magnitude = 4 V, the global maximum.
- ReadFrequency queries `:FREQ?` and returns the setting in Hertz. It does not measure the physical signal. A syntactically valid value outside 0.0001 through 15000000 is Device.

All requested numeric wire values use the previously qualified 12-significant-digit E11 formatter: uppercase `E`, signed exponent with at least two digits, .NET exponent padding normalized to Rust. Setter completion means guards and the write completed; there is no post-write query, tolerance or calibrated-output promise.

## Coupled voltage constraints

Manual printed 62 requires both `abs(offset) + vpp/2 <= 5` and `abs(offset) <= 2*vpp` for this 50 Ohm setup. Before a voltage write, validate both the original requested value and the value parsed from its rounded E11 wire representation against the queried counterpart, using these binary64 comparisons. This avoids knowingly issuing an auto-clamped pair. Queried current Vpp must be 0.05–10; queried current offset must have absolute value at most 4; an out-of-envelope numeric current setting is Device.

Structurally invalid requests fail before all IO and leave the session usable. A request can be structurally valid but incompatible with the current counterpart, discoverable only after queries. That coupled conflict is **InvalidArgument after IO**, with no write; this initial implementation conservatively quarantines after any failed operation that has already accessed IO, including this conflict. Do not promise that every InvalidArgument is detected without IO or preserves health. A malformed or wrong device state is Parse/Device and also quarantines.

## Reply and lifetime contract

Numeric bodies are strict ASCII decimal or scientific notation: optional leading sign, digits with an optional point and fraction digits, optional `E`/`e` exponent with optional sign and digits. A decimal point requires digits on both sides. Reject whitespace, headers, units, CSV, blocks and nonfinite values. Before the generic magnitude policy, the OUTP:LOAD? guard recognizes numeric positive 9.9e37 as the documented high-impedance setting (printed 151/PDF 153) and reports Device, stopping without a write. Other absolute values at least `1e30` are Parse. The high-Z exception applies only to this load guard, not arbitrary numeric queries. Readback numeric bounds and token checks are as above. These are software plausibility policies, not physical protection.

Serialize the complete operation. On IO, parse, Device or cancellation failure, quarantine before more traffic; no retry/reset/bus clear is emitted. Owned close occurs once; borrowed IO remains open. No device commands occur on close. Native async is optional and must be genuinely asynchronous; use SDK workers for blocking connectors. Recover through external resynchronization and reopen.

Independent cases must cover guard order and every failure point; frequency endpoints; amplitude/offset endpoints and rounded-wire coupled conflicts; usable structural rejection; post-query conflict and quarantine; malformed/numeric/token replies; always-on capability absence; passive open/close; ownership/quarantine and actual pending deadlines/cancellation. Run both languages, four frontends, source/packed Native AOT Windows/Linux x64 and .NET 8/10.
