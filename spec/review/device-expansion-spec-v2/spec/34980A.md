# Agilent / Keysight 34980A — mainframe contract v1

This is a proposed manual-derived software subset, not hardware validation. Primary evidence: `research/34980A-programming.pdf`, Keysight 34980A Multifunction Switch/Measure Unit Programmer's Reference, plus the own-module guides listed in `research/SOURCES.json`.

## One physical session

Canonical factory ID `keysight.34980a`; exact model `34980A`; case-insensitive manufacturer aliases `Agilent Technologies` and `Keysight Technologies`. Bind explicitly commissioned GPIB SCPI endpoints with scheme `scpi`. LAN/USB/serial host transport admission is deferred, without claiming those physical interfaces are absent. Metadata and opening send no commands.

A mainframe and its modules share **one opened connector and one SDK runtime lease**. Module views are capabilities of that handle, not separately opened driver instances. Every whole switch or digital operation executes under the same lock, including all guard queries and its final write/read. Failure/quarantine belongs to the parent session and affects every module view. Owned close closes the parent resource exactly once; borrowed close leaves it open. Neither close changes relay or output state.

## Frozen inventory and admission

Freeze a per-endpoint inventory before connector acquisition. Each slot is an integer 1–8 and has exactly one admitted module type: 34937A, 34922A or 34950A. Each logical switch channel or digital port is positive and unique in its own namespace. Each physical slot/local address can be bound at most once; duplicate logical IDs, duplicate physical addresses, conflicting types in one slot, unsupported local channels, empty usable inventory and unbound endpoint opens fail before IO. Copy all caller-owned collections so later mutation cannot change capabilities or mapping. Require 1–4096 endpoint bindings; reject normalized duplicate endpoint keys.

Derive the native channel address as `1000 * slot + local`, formatted as the unpadded decimal SCPI address (e.g. slot 2/local 1 becomes 2001). Never accept a redundant caller-supplied native address that can disagree with the validated slot/local values.

Required operations and execution modes must be checked against the selected endpoint's inventory, before acquisition. A relay-only endpoint must not advertise digital operations from another endpoint. Digital reads/writes are separately available according to admitted input/output ports. An operation on an unmapped logical channel/port or the wrong frozen direction fails before IO; it cannot fall back to another endpoint's route.

## Commissioning and scope

Require exclusive control of the entire mainframe, no active/internal/external-triggered scan, no monitor or route sequence, no autonomous buffered-memory/interrupt/pattern/trigger action that can change admitted IO, truthful installed-module inventory, suitable physical signal/load levels, no other controller/front-panel mutation, and a clean response boundary. The no-autonomous-actions commissioning condition must remain true for the entire handle lifetime, not only at open: exclusive software access does not disable an already-armed external INTR or pattern action. Guard queries observe current state, not future external triggers. No identity/module discovery, reset, preset, module reset, DMM enable, scan abort or global route change occurs implicitly. A bound inventory may be partial, so global OpenAll and checked shutdown are deliberately absent.

Support switching on 34937A and 34922A, and static byte digital IO on 34950A as specified separately. The internal DMM and 34922A acquisition/scan are deferred. Starting a DMM scan can open analog buses across slots, so it must not be implemented as an apparently isolated scalar channel operation without a future explicit mainframe-wide ownership contract. DMM enable can reset the instrument and is never a commissioning shortcut.

A complete-message connector enforces finite positive deadlines and a 256-byte allocation/body limit, removes only LF framing, preserves payload whitespace and rejects binary blocks before header processing. Standard VISA host support remains vendor-neutral in the core repo; all module addresses, command grammar and option rules stay in the external Keysight package.

## New neutral contracts

Extend the existing neutral Switch class with `CloseChannel(channel)`, `OpenChannel(channel)` and `ChannelIsClosed(channel)`. These describe one named normally-open/common path; they do not invent a matrix column or promise physical isolation. Existing paired `CloseRoute(ch1,ch2)` APIs remain separate and are not advertised by this factory.

Add neutral DigitalIo `ReadByte(port) -> u32` and `WriteByte(port, value: u32)`. Port must be positive; byte value is inclusive 0–255 and zero is valid. Read returns a sampled input byte, not an output latch; therefore only frozen input ports support ReadByte. Only frozen output ports support WriteByte. The selected endpoint advertises each operation only when it has at least one corresponding port, and per-port direction checks still precede IO. The core has no slot, model, polarity, module or SCPI vocabulary.

## Common failure contract and proof

Structural argument/inventory rejection before IO leaves the session usable. Once any host operation begins, IO, parse, Device or active-cancellation failures quarantine the shared parent. No automatic retry, drain, reset, route-open or digital-direction change is emitted. External resynchronization/recommissioning and reopening are required. Genuine native async is optional; blocking connectors use SDK workers with the same operation-level serialization.

Proof must cover shared-lease noninterleaving across module views, parent-wide quarantine, one owned close/borrowed preservation, isolated per-endpoint capabilities, immutable inventory and every slot/channel/direction boundary. Add independent exact traffic/value cases for each module. Execute source and packed Rust/.NET Native AOT consumers on Linux/Windows x64 and .NET 8/10; software simulation is not a physical bench claim.

## Concrete public construction

Rust module `hp34980` exports:

- `Factory::new(bindings: Vec<Binding>, connector: Arc<dyn Connector>) -> Result<Factory>`, plus optional `with_native_connector(Arc<dyn AsyncConnector>)` under the async feature.
- `Binding { endpoint: Endpoint, configuration: Configuration }`.
- `Configuration { commissioning: Commissioning, switches: Vec<SwitchChannel>, ports: Vec<DigitalPort> }`.
- `SwitchChannel { channel: u32, slot: u8, local: u16, module: Module }`; `Module` variants `Unknown`, `Hp34937A`, `Hp34922A`.
- `DigitalPort { port: u32, slot: u8, local: u16, direction: Direction }`; the module for these entries is always 34950A. `Direction` variants are `Unknown`, `Input`, `Output`.
- `Commissioning` variants `Unknown`, `NoAutonomousActionsConfirmed`; the latter affirms all commissioning conditions above, including stable electrical policy.

C# exposes `Hp34980Factory`, `Hp34980Binding`, `Hp34980Configuration`, `Hp34980SwitchChannel`, `Hp34980Module`, `Hp34980DigitalPort`, `Hp34980Direction` and `Hp34980Commissioning` with matching fields and enum semantics. The factory accepts bindings plus `IScpiConnector` and an optional genuine `IAsyncScpiConnector`. Configuration collections use read-only interfaces, but constructor validation copies them regardless of interface type. Unknown/undefined enum values fail before IO.

Derive each occupied slot's module from its bound paths/ports. A slot cannot contain both switch module types, or a switch module and a digital port. These cross-namespace conflicts fail even when logical IDs differ. The application may declare only used paths; the factory neither probes nor silently expands to all physical channels.

Register this one factory explicitly through `DriverRegistry`; do not append it silently to the generic profile list. Its descriptor advertises the union of configured capabilities, while each selected endpoint supplies and checks its own subset before acquisition. Neutral `Switch(handle)` and `DigitalIo(handle)` views share one handle. No module constructor opens a connector. Module names and slots remain in the external construction API, never core requests.
